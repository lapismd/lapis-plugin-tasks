# Tasks CI fan-out

Date: 2026-10-31

The flat Docker acceptance job is replaced by the Design Core lane split that
Tasks actually runs. Portable commands still enter through
`scripts/validation.mjs`. Turbo uses the same remote and local cache pattern as
Design Core: signed organization cache when `TURBO_TOKEN` and
`TURBO_REMOTE_CACHE_SIGNATURE_KEY` are present, and normal execution when they
are not. Governance and release preparation are uncached.

Required check names:

- Governance
- Quality
- Unit tests
- Native
- Static Storybook
- Storybook interactions (1/3)
- Storybook interactions (2/3)
- Storybook interactions (3/3)
- Dependency audits
- Validate

`main` has no branch protection and no rulesets. Validate is the release gate.
Version Packages and Publish and verify npm release still run only on `main`,
and publication still requires the `npm-production` environment. The qualified
tarball artifact remains `tasks-npm-<sha>`, produced by Validate after every
required lane succeeds.

`Publish Storybook to GitHub Pages` builds with the existing
`pnpm build-storybook` command and deploys to
`https://lapismd.github.io/lapis-plugin-tasks/`.

Local `pnpm validation:all` stays sequential in one Docker worker. This record
does not claim the new hosted lanes have passed.
