# Tasks plugin

`@lapis-notes/lapis-plugin-tasks` owns the first-party external Tasks catalog
and plugin runtime. A task is a Markdown file with YAML front
matter. The filesystem is authoritative. AppDatabase owns the public
`tasks/task` projection. The plugin registers a main-area planner view.
The runtime refreshes disposable effective-occurrence fields at date-sensitive
lifecycle boundaries without rewriting Markdown.
Opaque legacy repeat mappings remain projected as unsupported compatibility
data so planner editors can show and explicitly replace or remove them.
Host movable panels remain unspecified.
Reusable leaf controls come from public Design Core APIs.
`ApplicationTaskAreaPicker` is the catalog List picker and uses the standard
Design Core Command View presentation. `ApplicationTaskAtPicker` combines
day-part and clock-time choices, while `ApplicationTaskRepeatPicker` edits the
date-only RRULE recurrence model. The Today surface is a selected-date daily agenda with
configurable clock boundaries. Catalog adaptation keeps YAML `open`, `completed`, and
`canceled` on `Task.status` instead of collapsing canceled into done.
When labels are the date or undated bucket; At labels are the day-part.
A vault MAY include one `task-list-navigation` Markdown
file whose headings are sidebar sections and whose links pin root lists.
Task and task-list files remain arbitrary rich Markdown: H2–H6 headings provide
grouping context and contiguous unordered-list links to typed task documents
provide structural membership and safe sorting boundaries. There are no
reserved Items or Subtasks headings. The
`Plugins/Tasks/Panels` catalog story composes planner navigation, planner
body, and task detail with Design Core Column Canvas. That presentation is
not a host movable-panel runtime.
Selecting a list replaces only the planner body with the complete provider-
mounted Markdown file; the Column Canvas title remains workspace chrome.

This chapter is the package contract and the only normative MUST table. The
following chapters describe the implemented model:

- [Documents](./documents.md): Markdown kinds, heading paths, structural
  entries, and task runs
- [RRULE recurrence and habit tracking](./documents/recurrence.md): recurrence
  sets, effective occurrences, daily outcomes, tracking, and statistics
- [Runtime](./runtime.md): parse, project, query, and mutations
- [Lists](./lists.md): navigation pins, structural parents, and the sidebar
  tree
- [Planner](./planner.md): planner state, Column Canvas composition, daily
  agenda, and shared Task rows
