# Tasks Plugin

`@lapis-notes/lapis-plugin-tasks` owns the first-party external Tasks catalog
and plugin runtime. A task is a Markdown file with YAML front
matter. The filesystem is authoritative. AppDatabase owns the public
`tasks/task` projection. The plugin registers a main-area planner view.
Host movable panels remain unspecified.
Reusable leaf controls come from public Design Core APIs.
`ApplicationTaskAreaPicker` is the catalog list picker and composes Design
Core Command View. `ApplicationTaskAtPicker` is the planner `plan.at`
day-part dropdown. The Today surface is a selected-date daily agenda with
configurable clock boundaries. Catalog adaptation keeps YAML `open`, `completed`, and
`canceled` on `Task.status` instead of collapsing canceled into done.
When labels are the date or undated bucket; At labels are the day-part.
A vault MAY include one `task-list-navigation` Markdown
file whose headings are sidebar sections and whose links pin root lists.
Nested lists stay in each list’s `## Items`. The
`Plugins/Tasks/Panels` catalog story composes planner navigation, planner
body, and task detail with Design Core Column Canvas. That presentation is
not a host movable-panel runtime.

This chapter is the package contract and the only normative MUST table. The
following chapters describe the implemented model:

- [Documents](./documents.md) — Markdown kinds, front matter, and reserved
  sections
- [Runtime](./runtime.md) — parse, project, query, and mutations
- [Lists](./lists.md) — navigation pins, list-item parents, and the sidebar
  tree
- [Planner](./planner.md) — Column Canvas composition and bucket
  classification

## Requirements

| ID | Requirement |
| --- | --- |
| LN-TASK-001 | The standalone repository MUST ship `@lapis-notes/lapis-plugin-tasks` as a versioned first-party external package whose runtime manifest id is `tasks`, distribution is `first-party-external`, provenance is `official`, and `enabledByDefault` is `true`. |
| LN-TASK-002 | `TasksPlugin` MUST extend the public API `Plugin` surface. `onload` MUST register the public tasks projection and the main-area `tasks` planner view. It MAY register `tasks:open`, a ribbon item, the Tasks settings tab, and versioned plugin data governed by LN-TASK-029. |
| LN-TASK-003 | Production and Storybook source MUST receive `App` explicitly or from API context and MUST NOT read or assign `globalThis.app`. |
| LN-TASK-004 | The package MUST own the adapted Tasks catalog components and native `--ui-tasks-*` CSS. Reusable leaf controls MUST come from public `@lapismd/design-core` exports. |
| LN-TASK-005 | The published runtime MUST NOT depend on `@stevejuma/ui`, `@lapis-server/*`, `/Users/stevejuma/code/cv`, `@cvstudio/*`, `@lapismd/mira`, or Lapis Markdown. Package Storybook MAY depend on `@lapis-notes/workspace`, File Explorer, Search, and Markdown for shell stories. When those hosts load, Storybook MUST resolve a single CodeMirror and Lezer copy. |
| LN-TASK-006 | Package Storybook MUST run on port 7030, fail `pnpm test:storybook` on axe violations, and keep changed visual stories `visual-pending`. |
| LN-TASK-007 | Desktop and web hosts MUST register and load this plugin. They MUST NOT register Tasks workspace views, commands, or ribbon items themselves. |
| LN-TASK-008 | The public package export MUST include `TasksPlugin`, `TasksView`, `TASKS_VIEW_TYPE`, and the catalog components. It MUST NOT re-export Design Core `TaskDueCalendar`. |
| LN-TASK-009 | Autodocs Show Code MUST use public `@lapis-notes/lapis-plugin-tasks` imports, not story-only harness wrappers. |
| LN-TASK-010 | The planner MUST register as main-area view type `tasks` and fill the leaf with the Column Canvas composition from LN-TASK-012. Host movable panels remain unspecified. |
| LN-TASK-011 | CV-only `applicationId`, `linkedTo`, and `JobApplication` shapes MUST stay in catalog model fixtures and MUST NOT become canonical Task resource types. |
| LN-TASK-012 | Package Storybook MUST include a `Plugins/Tasks/Panels` Column Canvas composition of planner navigation, planner body, and closeable task detail without `AppShell`. Additional closeable columns MAY open from the selected task. This catalog canvas MUST consume public Design Core `column-canvas`, MUST fill the Storybook viewport without page-level scrollbars, MUST use the App Shell sidebar surface, MUST render the leading Tasks column without a column border so it blends into that surface, MUST render the sticky Tasks overlay without corner radius, MUST keep the planner column’s start corners complete, MUST clip the Tasks resize handle to those start corners, MUST size the leading Tasks column to the navigation labels and counts, MUST align the Tasks column header with the planner column header, MUST keep Tasks column hover and selected item states visible on the sidebar surface, MUST mount task detail directly in the detail column without an extra story wrapper, MUST place the Tasks resize handle on the planner column’s start border with no gap between those two columns, and MUST NOT register host movable panels. |
| LN-TASK-013 | `ApplicationTaskAreaPicker` MUST compose `@lapismd/design-core/shadcn/command-view` for the searchable list picker. It MUST NOT use native Command as that picker surface. |
| LN-TASK-014 | A canonical task MUST be a Markdown file whose front matter includes `type: task` and a stable `id`. The display title MUST be the first H1, else the filename. Child files MUST NOT store parent or list ids. |
| LN-TASK-015 | A canonical list MUST be a Markdown file whose front matter includes `type: task-list` and a stable `id`. Its display title MUST use a nonempty top-level front matter `title` when present, otherwise its first H1, otherwise a human-readable form of its stable id (for example, `list-docs` becomes `List Docs`). `list.status` MUST be `active` or `archived`. Lists MUST NOT be completable outcomes. List chips MUST show this display title rather than an available raw list id. |
| LN-TASK-016 | Task planning metadata MUST nest under `task:` with `status` `open`, `completed`, or `canceled`, and `start` `anytime`, `someday`, or a date. Inbox, plan, deadline, repeat, and comments MAY be omitted. When present, `plan.at` MUST be `anytime`, `morning`, `afternoon`, `evening`, or `HH:mm`. YAML MUST NOT store `today` or `upcoming` flags or task `plan.at: all-day`. |
| LN-TASK-017 | `## Checklist` MUST hold lightweight checkboxes only. `## Subtasks` MUST hold Markdown links to task files without wrapping checkboxes. `## Items` MUST hold links to task or task-list files. Other links MUST be ordinary references. |
| LN-TASK-018 | Inbox, Today, Anytime, Upcoming, Someday, Completed, Logbook, and daily Review MUST be derived query-AST wrappers over the public `tasks/task` projection. Completed MUST match only completed tasks; Logbook MUST match completed and canceled tasks. Overdue `plan.date` values MUST stay visible until the user reschedules, completes, skips, or cancels. Upcoming day rows MUST place open tasks by plan date or, when plan is omitted, deadline. Catalog adaptation MUST NOT treat a deadline-only task as undated anytime. |
| LN-TASK-019 | Mutations MUST edit one Markdown file or parent reserved-section links, then upsert the projection from that parse. Completing a linked child MUST update the child file. Rolling complete MAY reset only `## Checklist`. |
| LN-TASK-020 | Planner lists and cards MUST consume `TaskSummary` rows from the AppDatabase tasks projection. Detail and editor surfaces MAY load the Markdown `TaskDocument`. UI MUST NOT treat the database as authoritative. |
| LN-TASK-021 | Canonical catalog types MUST use the Markdown-first schema. Catalog planner fixtures MUST round-trip through task documents. Area membership MUST mean a task-list `## Items` parent. |
| LN-TASK-022 | Package Storybook MUST include `Plugins/Tasks/Shell` desktop and phone-width stories that boot a public `App`, load File Explorer, Search, Markdown, and `TasksPlugin`, seed planner Markdown, and restore a `tasks` leaf in `WorkspaceShell`. Both stories MUST finish their interaction play on the Today daily agenda with all five ordered sections present and the populated checklist progress for Review interview notes visible but collapsed, so opening the visual story documents the current Tasks surface rather than an intermediate acceptance state. Canvas stories MUST fill the available Storybook viewport. Docs embeds MUST stay height-capped. The live planner MUST use the same pinned clock as the repository snapshot. Show Code MUST use public package imports. |
| LN-TASK-023 | A vault MAY include at most one authoritative Markdown file whose front matter `type` is `task-list-navigation` and whose `id` is stable. Extra navigation documents MUST be ignored after a diagnostic. Headings in that file MUST be presentation sections, not resources. Links under those headings MUST pin root lists. The file MUST remain ordinary vault Markdown and MUST NOT live in plugin data. |
| LN-TASK-024 | A `list-item` link under a task-list `## Items` MUST be the only structural list parent. A `navigation-item` MUST be presentation only and MUST NOT count as a structural parent. A task-list MUST have at most one incoming `list-item`. Ordinary `reference` links MAY point at the same list from many places. Cycles in the list-item graph MUST be rejected. |
| LN-TASK-025 | The planner Lists sidebar MUST render Lists, then expandable navigation-section folders, then pinned root lists, then nested task-lists from outgoing `list-item` edges whose target `kind` is `task-list`. Section folders MUST default to expanded. All lists MUST be an expandable section folder for unpinned structural roots. Tasks MUST NOT appear in that tree. Selecting a section MUST NOT filter the planner. Opening a list MUST still show every `list-item` child, including tasks. |
| LN-TASK-026 | Reordering pinned roots, moving a list between sections, nesting, unnesting, and renaming a list or navigation section MUST rewrite one navigation or list Markdown file (or one reserved-section rewrite) and then reproject. Renaming a list with a front matter `title` MUST update that title as well as its H1. Creating a list from the area picker or the Lists tree MUST write a new `task-list` file. Creating a nested list MUST add a `list-item` under the parent. Archiving a list MUST set `list.status` to `archived` and omit that list from the sidebar tree. Deleting a list MUST unlink it from its parent or navigation pins, then remove the list file. Child task files MUST remain. Creating a task while an existing list is selected MUST attach that task to the existing list and MUST NOT mint a new list id such as `list-list-applications`. |
| LN-TASK-027 | The Lists tree MUST reuse Design Core Explorer indent-guide tokens and nested-sublist chrome. It MUST support inline rename and HTML5 list-tree drag with auto-expand. List rows MUST offer a Design Core context menu with Open note, Rename, New nested list, Unpin when the list is a pinned root, Archive, and Delete. Navigation-section folders MUST offer Rename except All lists, and New list. It MUST NOT mount `WorkspaceExplorer`. |
| LN-TASK-028 | The Column Canvas first column MUST use the same planner drop-host attributes as the App Shell sidebar so dragging a task over a bucket or list morphs the drag preview and highlights the drop target. |
| LN-TASK-029 | Tasks plugin data MUST be versioned and MAY store only plugin-owned presentation settings. `dayParts.afternoonStartsAt` and `dayParts.eveningStartsAt` MUST be valid ordered local `HH:mm` values and MUST default to `12:00` and `17:00`. The settings tab MUST expose both boundaries, reject invalid or unordered edits, serialize saves, migrate absent or malformed data to defaults, and notify open Tasks views after persistence. Changing settings MUST reclassify only clock-valued `plan.at` rows and MUST NOT rewrite task Markdown. |
| LN-TASK-030 | The package MUST publicly export `TaskDaySection`, `TaskPlannerDaySnapshot`, `TaskPlannerWeekDay`, and their pure routing and week helpers. The Today planner MUST be a controlled selected-date daily agenda. It MUST default from the injected local clock, present a Monday-first seven-day selector with previous- and next-week controls, distinguish actual today from the selected date, and expose a Column Canvas header action that returns to today whenever they differ. The selector itself MUST communicate the selected weekday and date; the agenda MUST NOT repeat that information in a separate oversized weekday/month banner. Selecting another date MUST change presentation only. The selected agenda MUST include open tasks whose plan date or deadline is on or before that date; Review MAY therefore retain the same overdue task. |
| LN-TASK-031 | The daily agenda MUST always present Anytime, Morning, Afternoon, Evening, and Done in that order. Each section header MUST keep its icon and title at the start while placing its item count in the trailing cluster immediately before the disclosure control. Explicit `plan.at` day parts MUST route directly; `HH:mm` MUST route through the configured boundaries; absent or invalid times MUST route to Anytime. The four open sections MUST default expanded, Done MUST default collapsed, every section MUST remain a drop target while empty or collapsed, and disclosure state MUST remain in memory across date changes without being persisted. Tasks-owned colors derived from neutral, warning, info, accent, and success roles MUST distinguish the sections accessibly. Done MUST contain completed tasks whose actual completion date equals the selected date; canceled tasks MUST remain Logbook-only. |
| LN-TASK-032 | Quick-create in an open daily section MUST write the selected plan date and matching `plan.at`. Dragging within or between open sections MUST persist order, selected date, and day part. Dropping into Done MUST complete at the injected clock; dragging out of Done MUST reopen and reschedule to the selected date. Completion MAY remove a row when its actual completion date differs from the selected date. Existing rolling recurrence advancement MUST remain authoritative instead of creating completion-history rows. |
| LN-TASK-033 | Task summaries and catalog adapters MUST expose optional checklist total and completed counts without embedding checklist contents. A task row whose total is nonzero MUST finish with a checklist footer after its application and list chips. The footer MUST be the final child of the whole task card, span its full width below both the content and trailing controls, and retain both bottom corner radii. The body above that footer MUST have square lower corners, including while hovered. It MUST have a separating top border, a subtly darker semantic surface, a compact progress bar and count, and an independent disclosure that defaults collapsed and lazily loads its `TaskDocument`. The trailing task-details control MUST be vertically centered with the task title line. Hovering the task body MUST NOT recolor the footer; its hover outline MUST instead frame the whole task card, including the footer. Hovering or focusing within the footer MUST use a separate footer-owned hover surface. Row, body, and opaque swipe-content surfaces MUST use the same hover timing so the title surface does not animate separately. When the row is selected, its selection surface MUST continue through the checklist footer; contiguous selected rows MUST square their joining body and footer corners so the selection outline does not leak at either side. Expanded items MUST use the public Tasks `ApplicationTaskCheckbox`, remain keyboard operable, and MUST NOT select, open, or drag the row. A checkbox write MUST identify the item by checklist ordinal and expected text, change only that Markdown marker, reparse, and reproject. A stale mismatch MUST leave the file unchanged, reload the checklist, and report an inline error. The row MUST update optimistically and roll back on failure. |
| LN-TASK-034 | A `type: task-list` document MAY contain one or more canonical `## Items` sections at any source position. Tasks MUST recognize a section only when every nonblank row before the next heading of equal or greater precedence is a supported top-level Markdown list link. Unsupported syntax MUST leave the complete section as ordinary Markdown. Recognition MUST retain each section's exact source range, authored link labels and targets, and link order without altering the source document. |
| LN-TASK-035 | `TasksPlugin` MUST register one plugin-scoped Markdown extension contribution without importing Lapis Markdown or Mira. Reading mode, embeds, and live preview MUST use one Tasks-owned rich Items block for recognized sections. Source mode, a live-preview selection inside the section, or its explicit source control MUST reveal the original Markdown. Task links MUST use the existing rich task row and checklist controls; task-list links MUST use linked-list rows; unresolved links MUST retain their authored label and target in a safe fallback. The Tasks-owned surface MAY enable planner selection, detail opening, quick-create, and drag ordering. Ordinary Markdown surfaces MUST keep task and checklist controls interactive while omitting planner-only selection, creation, and drag behavior. |
| LN-TASK-036 | Mutations to linked child task files MUST continue through `TaskRepository` and reproject from the new parse. An Items mutation in an active editable list surface MUST dispatch a CodeMirror transaction and use the Markdown editor's serialized save. A read-only Items mutation MUST guard the targeted section against stale source, rewrite only that exact section, reparse, and reproject. Multiple Items sections MUST remain independent, and surrounding front matter, headings, prose, whitespace, and later sections MUST remain byte-for-byte unchanged. |
| LN-TASK-037 | Selecting a task list in the Tasks workspace MUST mount the real `TFile` through the public Markdown file-surface provider and show the complete document exactly in source order, including front matter, headings, prose, and every Items section. Tasks MUST NOT synthesize, relocate, or separately filter an Items section. Double-clicking non-interactive prose MUST enter editable live preview; Escape or blur MUST flush before returning, failed saves MUST retain the dirty editor with an accessible error, metadata refresh MUST preserve a dirty buffer, and preview/edit modes MUST have one active vertical scroll owner. If no provider is registered, Tasks MUST fall back to the host's standard read-only Markdown renderer and keep an Open note action. |
